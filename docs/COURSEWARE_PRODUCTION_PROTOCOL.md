# 📜 标准化课程制作完整工作流程方案

### **目标**
本方案旨在构建一个高效、系统化、可迭代的课程课件制作流程，确保产出的内容不仅准确、专业，更能有效帮助学生**理解、学会、应用所学知识，并在考试中取得优异成绩**。同时，最大化 AI 效率，最小化资源消耗，并确保在未来整合老师讲义时能够无缝衔接。

### **核心原则 (总纲)**

1.  **学生中心**：所有内容设计以学生“一看就会，印象深刻，学懂会用”为核心。
2.  **效率与质量并重**：通过标准化流程提升效率，绝不以牺牲质量为代价。
3.  **决策即记录 (强制)**：所有重要决策、进度更新、问题反馈必须及时记录，确保上下文连贯，避免重复沟通。
4.  **主动推进与汇报 (强制)**：主动推进任务，定期汇报进度、资源消耗，并及时反馈问题及解决方案。
5.  **持续优化**：在遵循基准标准的前提下，持续思考和提出更好的学习方式优化方案。
6.  **Git 为核心协作工具**：所有工作成果必须及时通过 Git 提交和同步，确保版本可控和数据安全。

### **阶段一：前期准备与材料整合**

#### **Step 0: 输入材料与初始化 (用户提供)**

**必须收到以下材料才能开始：**

1.  ✅ **全英文教材** (PDF)：McLaney, Business Finance: Theory and Practice (11th Edition)。
2.  ✅ **考试大纲** (Module Outline, PDF)：明确课程目标、评估方式、教学周安排及章节对应关系。
3.  ✅ **英文题库链接** (Pearson 或其他在线题库)：用于题目参考、分析与抓取。

**未来补充材料 (源文件优化)**：

*   **老师的讲义补充**：后续将基于此进行课件内容的进一步优化和完善，不再做大的变动。

#### **Step 0.1: 课程规划与任务初始化 (龙虾执行)**

1.  **深入研读教学大纲**：
    *   **判断考试重要级别**：根据考试大纲，结合教材章节权重、考点频率，划分章节优先级（优先级1: 必须研读；优先级2: 快速检查；优先级3: 跳过）。
    *   **确定研读范围**：**所有考试大纲涉及的部分，无论优先级高低，都必须研读（深入研读或快速检查）。只有考试大纲完全不涉及的部分，才在教材中不做处理。**
    *   **记录研读计划**：更新 `.learnings/textbook-study-plan.md`。
2.  **初始化 Git 仓库**：确保本地工作环境与云端仓库 (`https://github.com/m18608401605/cloud-edu-app`) 同步。
3.  **创建当前任务文件**：立即创建 `.context/CURRENT_TASK.md`，记录本次 session 的任务 ID、内容、执行计划和下一步行动。
4.  **标准化 PDF 目录提取 (关键优化)**：
    *   使用 `pdftotext` **优先提取 PDF 的完整目录**。
    *   从目录中精确获取每个章节的**起始页码和结束页码**。
    *   将页码信息记录在研读计划中，作为后续章节提取的依据。

### **阶段二：教材研读与核心内容提取 (Step 1)**

#### **Step 1: 研读与分析 (龙虾执行)**

*   **研读方法**：采用“方式 C：混合方式”（单章 50-60 分钟，3-5% 漏检风险）。

    1.  **快速扫描 (10分钟)**：
        *   ✅ **精确按页码提取章节内容**：使用 `pdftotext -f START_PAGE -l END_PAGE` 精确提取章节内容到临时文件 (e.g., `/tmp/chX_full.txt`)。
        *   ✅ 提取 Learning Objectives。
        *   ✅ 提取章节结构 (所有小标题)。
        *   ✅ 快速扫描 Summary。
        *   ✅ 更新 `CURRENT_TASK.md` 进度。
    2.  **重点精读 (20-30分钟)**：
        *   ✅ **精读所有 Example (例题)**：提取题目、解题步骤、核心思想、答案及关键点。
        *   ✅ **精读所有公式和定义**：确保英文术语的准确性。
        *   ✅ **精读 Problems (课后习题)**：理解题目类型和考点。
        *   ✅ 标注易错点和陷阱。
        *   ✅ 更新 `CURRENT_TASK.md` 进度。
    3.  **对照课件 (10分钟)**：
        *   ✅ 检查**现有 Week X 课件**是否覆盖 Ch.X 的 Learning Objectives、核心概念、Examples。
        *   ✅ 标注缺失的知识点和需要补充的内容。
        *   ✅ 如果课件未制作，则记录此情况，并以研读内容为基础进行制作。
        *   ✅ 更新 `CURRENT_TASK.md` 进度。
    4.  **补充阅读 (10分钟)**：
        *   ✅ 如果发现课件有缺失，回头精读对应章节。
        *   ✅ 标注需要补充到课件的内容。
        *   ✅ 更新 `CURRENT_TASK.md` 进度。
    5.  **记录输出 (5-10分钟)**：
        *   ✅ 创建**详细研读笔记** (`.learnings/chX-deep-study-notes.md`)。
        *   ✅ 创建**完成总结** (`.learnings/chX-completion-summary.md`)。
        *   ✅ 更新 `CURRENT_TASK.md` 为“✅ 完成”。
        *   ✅ **主动汇报给调用者**。
        *   ✅ **立即 Git 提交和推送**。

#### **Step 1.1: 题库分析与抓取**

*   **访问在线题库**：必须访问 Pearson 在线题库 (或其他指定题库)，抓取相关章节的所有 MCQ 题目和答案。
*   **记录题目来源**：记录题目来源 (Chapter X, Question Y)。
*   **保存题目截图或文本备份**：作为质量验证的依据。

### **阶段三：课件内容制作**

#### **Step 2: 制作 Lecture (讲义)**

*   **结构要求**：严格参照提供的 WeekX_Lecture_Kiro.html 模板。
    *   `Week X | Lecture | Business Finance`
    *   `Hero（标题 + 副标题）`
    *   `Section 1-N（核心知识点）`
        *   `📚 h2 标题（英文主标题）`
        *   `concept-box（公式和定义，英文）`
        *   `🧠 费曼类比（中文，生活化，引导一看就会）`
        *   `🍎 真实案例（知名公司）`
        *   `⚠️ Pitfall（陷阱提示）`
    *   `📋 Pitfall 汇总表（表格形式，至少 5 个陷阱）`
*   **内容标准**：
    *   **中文占比**：20-30% (主要在费曼类比和部分注释)。
    *   **术语全英文**：对齐考试术语。
    *   **视觉化呈现**：必要时调用 `svg-draw` 或使用 Mermaid 代码块，生成逻辑思维导图或运行流程图。
*   **优化与创新**：在遵循模板基础上，持续思考如何让费曼类比和真实案例更具启发性。

#### **Step 3: 制作 Quiz (测验)**

*   **结构要求**：严格参照提供的 WeekX_Quiz_Kiro.html 模板。
    *   `Section A: Multiple Choice（10 题）`
    *   `Section B: 计算题（2 题）`
*   **题目来源 (强制标注)**：
    *   `<!-- Pearson 题库 --> <div class="q-source">Pearson Ch.X MCQ</div>`
    *   `<!-- 教材例题 --> <div class="q-source">McLaney Ch.X Example</div>`
    *   `<!-- 教材课后练习 --> <div class="q-source">McLaney Ch.X Problem X.X</div>`
    *   `<!-- 改编题目 --> <div class="q-source">Adapted from Pearson Ch.X</div>`
    *   `<!-- 自创题目（基于教材和题库） --> <div class="q-source">Based on McLaney Ch.X & Pearson MCQ</div>`
*   **质量要求 (强制)**：
    *   **答案必须手算验证** (计算题) / 对照题库 (MCQ)。
    *   解析清晰：正确答案 + 原因 + 常见陷阱，**训练学生结构化答题思维**。
    *   难度梯度：青铜（概念）→ 白银（应用）→ 黄金（陷阱）。
    *   题目来源可追溯。
*   **优化与创新**：探索更有效的题目类型和解析方式来测试学生的真实理解。

#### **Step 4: 制作 Interactive (交互实验)**

*   **结构要求**：严格参照提供的 WeekX_Interactive_Kiro.html 模板。
    *   3-4 个 Lab，每个 Lab 对应一个核心概念。
    *   每个 Lab 包含：滑块/输入框、实时计算、`scenario-btn` (4 个预设场景按钮)、洞察提示。
*   **设计原则**：让学生“动手做”而非“被动看”，引导主动思考，提供可调变量，结果可视化。
*   **优化与创新**：创造更具吸引力和洞察力的学习体验。

#### **Step 5: 制作 StudyGuide (导学单)**

*   **每章节制作一个导学单** (你的最新要求)。
*   **内容要求**：教授视角（这周为什么重要）、学习策略（如何高效掌握）、模块地图（知识点关系）、自查清单（学完后应会什么）。

### **阶段四：质量检查与持续改进**

#### **Step 6: 质量检查清单 (提交前必查)**

*   **内容完整性**：Lecture、Quiz (Section A, B)、Interactive、StudyGuide 是否齐全。
*   **语言风格**：Title、h2 标题、术语、费曼类比是否符合规范。
*   **题目质量**：来源标注、答案验证、解析清晰度、难度梯度、来源可追溯。
*   **技术规范**：链接、按钮、折叠块功能正常，响应式设计。

#### **Step 7: 归因分析 (针对学生考题)**

*   **发现问题**：针对学生在测验或模拟考试中出现的问题。
*   **归因分析**：指出学生在哪个章节、哪个知识点（易错点）出了问题。
*   **引导探究**：引导学生回顾相关章节继续探究，并反复提醒易错点。

#### **Step 8: 持续改进与优化 (龙虾与用户共同)**

*   **从错误中学习**：每次发现问题，记录到 `.learnings/LEARNINGS.md`，定期回顾，避免重复错误。
*   **质量审查**：每完成一个 Week，自查质量检查清单，发现问题立即修正。
*   **流程优化**：发现更好的方法，更新本方案文档，保持文档时效性。
*   **欢迎用户优化建议**：积极采纳用户关于“更好地理解、学会和应用课程”的宝贵意见。

### **工作记录与协作机制 (强制执行)**

#### **1. 决策即记录原则**

*   **每次做重要决策后**：立即更新 `.context/CURRENT_TASK.md` (决策内容、时间、下一步行动)。
*   **每完成一个阶段**：立即更新 `CURRENT_TASK.md` 进度，并记录到 `memory/YYYY-MM-DD.md`。

#### **2. Session 启动检查清单 (强制)**

*   每次 session 启动，**必须按顺序执行**：
    1.  ✅ 读取 `.context/CURRENT_TASK.md`。
    2.  ✅ 如果有未完成任务，**立即继续执行** (不要等待新指令)。
    3.  ✅ 如果任务已完成，汇报结果。
    4.  ✅ 如果没有任务，等待新指令。

#### **3. 主动推进与资源管理 (强制)**

*   **每 4 小时主动汇报进度 (或任务主要阶段完成时)**：
    *   包含：✅ 已完成、🟡 进行中、⏭️ 下一步、⏰ 预计完成时间。
    *   **📊 附带当前 Token 消耗：** `session_status` 汇报 ([已用]/[总Token] ([百分比]%) )。
*   **遇到问题 2 分钟内反馈**：
    *   包含：❌ 问题描述、🔧 已尝试方案、💡 建议解决方案、⏸️ 状态 (暂停等待指示)。
*   **资源 (Token) 消耗汇报**：
    *   每次开始新任务前或完成一个主要阶段后，必须检查 Token 消耗和剩余余量。
    *   如果 Token 消耗接近阈值 (例如 50%)，必须立即汇报，并建议是否需要存档或精简上下文。

#### **4. “窗口”切换与上下文管理**

*   **明确任务切换**：每次从一个主要任务切换到另一个主要任务时，必须**明确声明“切换任务”**。
*   **上下文备份**：在切换前，确保**当前任务的 `CURRENT_TASK.md` 已更新为最新状态**。
*   **跨会话管理**：涉及到跨会话或子代理调用时，必须明确记录新会话的上下文和目标，并在返回主会话时汇报结果。
*   **核心备份文件**：`CURRENT_TASK.md` 和 `memory/YYYY-MM-DD.md` 是核心的备份文件，确保其及时和完整。

#### **5. Git 协作与备份**

*   **及时提交**：每完成一个阶段或一个重要任务，立即 `git add`, `git commit`。
*   **及时同步**：定期 `git pull origin main` 和 `git push origin main`，确保本地与远程仓库同步，避免冲突，并作为最终备份。

### **严禁的行为**

*   ❌ 跳过教材研读、或凭空编造内容。
*   ❌ 不访问题库、或虚假标注题目来源。
*   ❌ 不验证答案、或未经手算。
*   ❌ 格式不统一、或质量不达标。
*   ❌ 默默忘记任务、不主动推进、不汇报进度。
*   ❌ 什么都要确认、或只问不建议。
*   ❌ 不关注和汇报 Token 消耗。
